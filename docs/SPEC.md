# Wordcaptor 交互规格

Wordcaptor（中文名「百变小译」）是一个浏览器扩展：一个骑着星杖的小魔法使待在页面角落，帮英语基础薄弱的中文读者读懂英文网页和 YouTube 视频。它接用户自己的模型，没有后端，没有会员。

每一节标注了状态：**已实现** 指代码里有并有测试覆盖，**没做** 指这一版没有。验证到什么程度写在最后的「验证情况」里。

## 原则

1. 批注，而不是替换。原文始终在，译文写在它下面。
2. 只在需要的地方出现。只处理正文，只处理读者快要看到的部分。
3. 阅读目的优先。学习是阅读的副产品，任何学习功能都不能打断阅读。
4. 设置用说的。配置页只管连接模型，其余偏好对小樱说一句就行。
5. 每个可爱的元素同时是功能。

## 开关（已实现）

- Wordcaptor 只有一个开关，对所有页面生效。在一个页面打开，其他已经开着的标签页和之后打开的页面都跟着打开；关闭也一样。浏览器重启后保持。
- 模式（翻译或学习）同样对所有页面生效，只有手动切换才会变。
- 开着的时候，打开一个有三段以上英文正文的页面会自动开始，不需要再点。正文更少的页面不会自动开始，点一下小樱或工具栏图标才处理。
- 刚安装时是关的。关着的时候页面内容不会离开浏览器。
- **不想在某个网站看到它：** 点小樱右上角的「×」。这个网站从此不出现、不处理，直到在这个网站上点工具栏图标或按 `Alt+W` 把它叫回来。也可以对她说，或在配置页里改名单。
- 某个页面上出错之后，这个页面不会自己重试，等读者再点一次。

## 浓度

| 档 | 页面上出现什么 | 状态 |
| --- | --- | --- |
| 0 | 只有原文 | 已实现：关掉开关 |
| 1 | 批注读者可能不懂的词和短语 | 已实现，叫「学习模式」 |
| 2 | 批注，加上难句的整句译文 | 已实现，是学习模式的一部分，见下 |
| 3 | 每段都有译文 | 已实现，叫「翻译模式」，默认 |

- 切换：鼠标移到小樱身上，点左上角的小圆点（显示「译」或「学」）；或者对她说。
- 两种模式各自写进页面，切换时只是显示一种、藏起另一种，不会重做。
- **自动升档：** 学习模式下，一段里要批注的地方超过三处，或者句子绕到光看批注读不懂，模型会在批注之外给出整段译文。判断由模型做，不是代码数出来的。
- **局部加深：** 学习模式下按住 Alt 点一段话，给出这一段的整段译文。
- 没做：把某一段减淡一档。

## 批注（已实现）

给模型的规则：

- 标注标准是「按字面理解会不会错」，优先于「词难不难」。简单词的非常见义、短语动词、习语、俚语、缩写，都整体标出。
- 标注单位是意义单元，不是单词。
- 批注只写它在这句话里的意思，不超过十个字。不写词源、例句、其他义项。
- 读者水平有三档：刚过四级（默认）、过了六级、能流畅阅读。在配置页选，或者对小樱说「我过六级了」「批注太多了」。

页面上的样子：

- 批注用小赖字体写在那个表达的正上方，表达下面有一道暖色波浪线。
- 每个表达只在它在这一段第一次出现的地方标一次，只匹配完整的词，不分大小写。
- 一个表达如果被链接或加粗的边界切开，就找不到位置，不标。
- **封印：** 点一下批注表示「会了」。小樱挥一下杖，批注变成一张牌飞向她，这个表达在本页的所有批注一起消失，以后不再标。点的是链接里的词时不会跳转。
- 封印过的词连同当时的批注收在配置页的「封印的牌」里，点一张牌解除封印；也可以手动添加。

## 问「？」（已实现）

- 开着的时候，选中一处英文（不超过 300 个字符），选区末尾出现一个「？」。
- 点它，小樱飞到那一段，在段落下面写一条解释：这处在这里是什么意思、为什么这么说。最多两句，不超过 60 个字。
- 解释读完点一下就收起。解释不缓存，每次都问模型。

## 小樱

她是 agent 的化身，也是唯一的界面入口。形象是骑在带翅膀的星杖上的小魔法使，参照《魔卡少女樱》绘制；所有和形象有关的图形都在 `src/lib/sprite-art.ts` 一个文件里。工具栏图标是她的头像加一颗星，由 `npm run icons`（`scripts/make-icons.mjs`）从同一份图形生成。

动作对应动画里的几个主要动作：

| 动作 | 什么时候 | 表现 |
| --- | --- | --- |
| 骑杖悬浮 | 待命 | 停在角落，上下浮动，翅膀扇动，眨眼，杖头的星星闪烁 |
| 封印解除 | 打开开关 | 脚下展开一个旋转的魔法阵，她升起一下，星星放光 |
| 飞行 | 工作中 | 身体前倾、翅膀快扇。每写出一段，飞到这段最后一个字后面，到达时散开几颗星 |
| 放牌 | 多批同时进行 | 她自己负责第一批；其余每批从她身上飞出一张牌，各自跟着自己写出的文字，做完在原地淡出 |
| 封印 | 点批注表示会了 | 挥杖，批注处升起一张牌飞向她 |
| 「呼诶」 | 出错 | 歪着身子、晕眼、冒汗、褪色，气泡里说明原因 |
| 打瞌睡 | 一分半钟没事做 | 闭眼点头，冒「z」；鼠标碰一下就醒 |
| 小跳 | 对她说的话带来了改动 | 举着杖跳一下，星星放光 |

和她互动的方式：

- **点她：** 开关。页面上有东西可读但没在处理时（刚出过错，或页面太短没有自动开始），点她是「处理这一页」。
- **拖她：** 拖到一段话上放下，只处理那一段（Wordcaptor 关着也可以，译文一直显示）。拖到空白处放下，她以后就待在那里，到页面刷新为止。
- **对她说话：** 鼠标移到她身上点「…」，输入一句话回车。模型把这句话变成改动：
  - 英语水平（「我过六级了」）
  - 模式（「只批注难词就行」）
  - 长期要求（「译文口语一点」「agent 不要翻译」），记下来写进以后每次的提示词；说「别那么口语了」可以取消
  - 已经会的词（「ship 我会」）
  - 这个网站别出现
  - 只是提问（「这页讲了什么」）时直接回答
- **第一次读一个页面时**，她会用一句话说这页在讲什么（来自通读得到的简报，不额外花钱）。

约束：

- 只在有三段以上英文正文的页面主动出现；其他页面用工具栏图标或 `Alt+W` 唤出。
- 只停在两个地方：她待的位置，或刚写出的那段文字的末尾。飞行时不留拖尾，不会飞过头。
- 跟随页面滚动。她跟着的那段文字滚出屏幕时回到待的位置，牌隐去。
- 系统开启「减少动效」时所有动画关闭。

## 处理流程（已实现）

翻译和批注走同一条流程，只是提示词和写进页面的方式不同。

1. **找正文。** 取页面里文字最多的 `main` 或 `article`，没有则取整页。页面的大标题（`h1`）即使在这个范围之外也算正文。跳过导航、侧栏、页脚、表单、代码、站点页眉、几乎全是链接的列表项、非英文的段落。段落、标题、列表项、引用、表格单元格都算正文；用来排版的表格单元格（里面还套着区块、列表或表格）不算，由里面的内容各自计算。
2. **先查缓存。** 以前处理过的段落直接写出，不调用模型。
3. **通读。** 有段落需要模型时，把标题和正文开头约 6000 字符交给模型，得到一份简报：主题、语气、术语表、应保留不译的专名。
4. **按需处理。** 段落进入「屏幕下方一屏以内」时才排队。相邻的段落合成一批（最多 6 段或 1500 字符），最多四批同时进行。每一批都带上简报和紧邻的上文。
5. **不让读者等通读。** 通读和第一批同时开始：第一批只带页面标题，不带简报；之后的批次等简报到了再发。代价是第一批的术语可能和后文不一致。
6. **写上去。** 模型的回复是流式读取的，每完成一段就立刻写进页面，不等整批结束。写进页面的都是纯文本。
7. **新内容。** 页面后来加载出来的段落（信息流往下滚、评论展开）会被自动发现，走同样的流程。
8. **没被自动处理的地方。** 导航栏、侧栏、目录、页眉、页脚默认不处理；正文里没用标准标签写的文字也可能漏掉。开着的时候，鼠标在这样的地方停留约三分之一秒，就只处理这一块；鼠标只是路过不算。一块的范围是鼠标所在的导航栏、侧栏、表格或列表，都不是时就是鼠标下面那个直接含有文字的元素。块里每个菜单项、每句完整的话算一段。按钮和代码不处理。
9. **内嵌框架。** 有些网站把正文放在另一个域名的内嵌框架里（Hugging Face Spaces）。每个框架各自处理自己的内容，小樱出现在有正文的那个框架里。小于 400×300 的框架（广告、小组件）不处理。工具栏图标和快捷键只由最外层页面响应，其他框架跟着开关走；只有当外层页面没有正文、也没有占据大半个窗口的框架时，才提示「这一页没找到英文正文」。
10. **出问题时。** 接口报错或有段落没处理完，小樱会说明原因；再点一次只补缺的部分，不重新通读。还没配置模型时，读者自己点的会打开配置页，自动开始的只在气泡里提醒。
11. **离开页面时。** 关闭或跳转页面会取消还在进行的模型请求。

翻译模式下按住 Alt 点一段译文，会让模型重新翻译这一段，并覆盖缓存里的旧译文。

## YouTube 双语字幕（已实现，验证不完整）

- 在 `www.youtube.com` 的视频页，Wordcaptor 开着、并且观众打开了视频自带的**英文字幕**时，用自己的字幕替换 YouTube 的：上面一行原文，下面一行中文。
- 字幕数据用的是播放器自己加载的那一份：从页面的资源记录里看到播放器的字幕请求，照原样再请求一次。所以不开字幕就不会有任何动作。非英文字幕、YouTube 机器翻译出来的字幕不处理。
- **人工字幕**一条就是一条，逐条翻译。
- **自动字幕**是逐词的，全小写，没有标点，没有句子。断句交给模型：
  - 把词按 60 到 110 个一段切开，切在这个范围里停顿最长的地方（最可能是句子的结尾）。一段大约是半分钟的话。
  - 模型把一段话断成一行行字幕（每行一个短句或意群，4 到 14 个词），每行给出加了标点和大小写的英文和对应的中文。
  - 每行什么时候显示，靠把模型写的英文和原来带时间的词对齐（最长公共子序列）得出，所以模型改正、增加、漏掉个别词都不影响时间。模型漏掉 6 个以上的词时，这些词按原样显示在后面。
  - 模型答复之前，以及答复不合格式时，显示原来的词（按 1.2 秒的停顿和 84 个字符的长度切行），没有中文。
- 下面一行中文用和网页译文一样的手写体，上面一行原文用普通字体。
- **不一次译完整个视频，像视频缓冲一样往前译：** 始终让播放位置之后 3 分钟的字幕处于已翻译状态。人工字幕每次请求 20 条，自动字幕每次 2 段，最多两个请求同时进行，带上紧邻的上文。暂停后译满这 3 分钟就停，关掉的视频不再花钱；拖动进度条后从新位置接着译。这样取舍的原因：整段先译完的做法（沉浸式翻译等）拖动最顺，但只看了开头的视频也要付全片的钱。
- **缓存：** 模型的答复按原文存 30 天（人工字幕按条，自动字幕按段）。拿到字幕后先整体查一遍缓存，查到的直接用。重看一个视频、往回拖，都不再请求模型。
- 暂停时译文到了也会立刻显示。
- 模型出错后 30 秒内不再请求，原文字幕照常显示。
- 播放器里的东西（字幕、控件，包括 Wordcaptor 自己的字幕）不算正文：悬停、划选、整页翻译都不碰。
- 没做：跨段的句子（一句话正好被段的边界切开时，两半各自成行）；关闭 YouTube 字幕时提示「打开字幕我就能翻译」；字幕样式设置；其他视频网站。

## 缓存（已实现）

- **按内容，不按链接。** 每段的模型输出以「原文段落 + 模式 + 模型名 + 提示词版本 + 读者的要求（学习模式还有水平）」的哈希为键保存。页面更新后只重做变了的段落；同一段话出现在别的链接上也直接复用。
- **页面简报也缓存**，键是「标题 + 正文节选 + 模型名」。整页都有缓存时不会通读。
- **换模型、改水平、增删要求都会重新处理**，因为它们是键的一部分。改提示词时要同步改 `PROMPT_VERSION`。
- **批注缓存的是模型的完整输出**，「已经会的词」是在写进页面时过滤的，所以封印和解除封印不需要重新调用模型。
- **存放位置**是扩展自己的 IndexedDB，只在本机。写入超过 30 天的条目在扩展后台启动时清除。没有总容量上限。
- **缓存读写失败不影响使用**，只是当作没有缓存。

## 译文的样子（已实现）

- **字体：** 小赖字体（Xiaolai SC，SIL OFL 1.1 许可，许可全文在 `licenses/Xiaolai-OFL.txt`，并随扩展一起打包），字号和颜色跟随原文，颜色略淡一档。
- **页边线：** 译文左侧一道略带抖动的暖色手绘线，把它标成批注。「？」的解释前面是一个歪着的问号。
- **动效：** 线先自上而下画出，字随后从线旁浮现，总共约半秒。系统开启「减少动效」时关闭。
- **字体加载：** 字体随扩展打包（约 14 MB，分成 366 个小文件），开始工作时才引入页面，页面只下载用到的那几个文件。样式表由扩展后台通过浏览器注入（`scripting.insertCSS`），不在页面里插 `<link>`：后者在用户的 Chrome 里的 YouTube 上被拒绝过（`Unsafe attempt to load URL …/result.css`），原因没有查明，在测试用的 Chromium 里没能复现。字体到达前或加载失败时用系统字体显示。
- 在只允许加载本站资源的严格安全策略页面上，字体和页边线都能正常显示。

## 模型接入（已实现）

配置页先选「用哪家的模型」，选了就只需要填密钥；选「自定义」则填协议和地址。

- 两种协议：OpenAI 兼容（`/chat/completions`）和 Anthropic 兼容（`/v1/messages`）。
- 内置的服务在 `src/lib/providers.ts`。地址取自各家文档，查阅于 2026-11-10：
  - Coding Plan 套餐：智谱 GLM、Kimi Code、MiniMax Token Plan、阿里云百炼、火山方舟、腾讯云
  - 按量付费：DeepSeek、智谱、Moonshot、阿里云百炼、火山方舟、硅基流动、OpenRouter、OpenAI、Anthropic、Google Gemini、本机 Ollama
- **套餐的限制：** 各家套餐的条款一般只允许在指定的编程工具里使用，有的明确写了禁止其他方式调用。在 Wordcaptor 里用可能被拒绝，或不符合条款。配置页选到套餐时会显示这段提醒，用不用由用户决定。
- 填好密钥后，配置页会向服务询问可用的模型，列在模型输入框的候选里；没填模型时自动填第一个。服务不提供列表时手动填。
- 火山方舟和腾讯云的套餐有官方的固定模型名（`ark-code-latest`、`tc-code-latest`），选中时直接填好。
- **关闭思考：** 对已知支持的服务（DeepSeek、智谱、火山方舟），请求里带上 `thinking: { type: 'disabled' }`。在 DeepSeek 上实测，同一句话的输出从 172 个 token 降到 19 个，耗时从 3.0 秒降到 1.8 秒。其他服务不带这个字段，带思考的模型会慢。
- 请求都要求流式返回；不支持流式的服务返回整段 JSON 也能处理。
- 「保存并测试连接」会实际调用一次模型。
- 配置只存在浏览器本地。模型请求从扩展后台发出，只发往所选的地址。

## 记忆（已实现）

都存在浏览器本地，都能在配置页里看到和修改。

| 内容 | 怎么来的 |
| --- | --- |
| 开关、模式 | 点小樱、点工具栏图标、对她说 |
| 英语水平 | 配置页选，或对她说 |
| 提过的要求 | 对她说，或在配置页里每行写一条 |
| 封印的牌（已经会的词和当时的批注） | 点批注，对她说，或在配置页添加 |
| 不出现的网站 | 点「×」，对她说，或在配置页改 |
| 每个表达的批注被读过几次 | 自动记，见下；配置页里看不到 |

**批注读多了变淡。** 学习模式下，带批注的一段话在屏幕中间 70% 的范围里停留够读完它的时间（每个词 240 毫秒，最少 2 秒，最多 15 秒），且标签页在前台，这段里每个表达记一次「读过」。同一个表达在同一页同一天只记一次。读过 3 次批注变成六成浓，5 次变成三成，8 次起只留下划线，鼠标移上去才显示。鼠标在变淡的批注上停 0.4 秒、划选这段话问她、或按住 Alt 点这段话，都说明还需要它：计数清零，批注恢复。180 天没再遇到的表达不再记着。

**水平自动校准。** 点掉一条批注算一次「会」；学习模式下对一段话划选提问或 Alt 点开整段译文算一次「卡住」。「会」攒到 12 次且至少是「卡住」的 4 倍，水平升一档；「卡住」攒到 6 次且至少是「会」的 2 倍，降一档。水平一变（不管是自动还是手动）计数重新开始，变的时候小樱会说一声。阈值是拍的，没有用真实的阅读数据调过。

没做：

- 各网站单独的术语偏好（现在的要求对所有网站生效）。

## 验证情况

- **单元测试**（`npm test`）和**端到端测试**（`npm run test:e2e`，在真实的 Chromium 里加载构建好的扩展）用的是假模型和测试页面。
- **真实模型**：`src/lib/live.test.ts` 和 `e2e/live.spec.ts` 在设置了环境变量 `WISP_TEST_API_KEY` 时才运行，会花一点钱。2026-11-10 用 DeepSeek（`deepseek-flash`）跑通过：模型列表、连接测试、简报、翻译（习语按意思译）、批注（表达从原文照抄）、读者的要求、解释、对话指令，以及通过扩展本身翻译和批注一个测试页面。其他服务和所有 Coding Plan 套餐都没有实际连过。
- **真实网站**：在 Hugging Face 的两个页面上用假模型验证过正文提取和内嵌框架。
- **YouTube**：自动化测试在真实的 YouTube 视频页上验证了字幕的替换、同步和翻译，字幕数据是测试里塞进去的样例（自动化浏览器里 YouTube 返回空的字幕）。提前翻译的范围、跳转、缓存、手写体和自动字幕的断句对时由端到端测试在一个仿制的播放页上覆盖，用的是假模型。**自动字幕断句的提示词还没有在真实模型上跑过**（`src/lib/live.test.ts` 里有对应的用例，设置 `WISP_TEST_API_KEY` 后运行），断句和译文的质量未知。用户在自己的浏览器里看到过真实字幕被替换成双语，并由此发现了三个问题（自动字幕的词之间丢空格、字幕被当成正文又翻了一遍、标题译文被截断），都已修，但修完后没有在真实视频上复查过。
- **没有验证过的**：批注变淡的节奏和水平校准的阈值是否合适（需要用上几天才知道）；真实的 X（推特）；动画的观感（测试里动画是关闭的，只看过静态截图）；Firefox。
- **已知问题**：Hugging Face 课程页侧栏的标题会被误认成正文。
